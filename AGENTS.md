# Architecture rules

- AML/CFT policy families are consumed only from the component pinned in `supervisory_assessment_policy_snapshot` (via `supervisory_assessment_pinned_component_internal`), never from "current active" config — so later versions never alter an existing assessment.
- Sector overlay, fact configuration and source binding are enforced in the database commands (`supervisory_assessment_fact_set` / `_fact_override` / snapshot stamp); the browser only displays `supervisory_assessment_configuration_authority` — client checks are not a boundary.
- Configuration immutability is proven with the content fingerprint (`supervisory_policy_component_content_fingerprint`, cfp1, excludes lifecycle metadata) via `supervisory_assessment_policy_basis_integrity`; the legacy status-inclusive `content_hash` values stored in snapshots are historical and are never recalculated — so lifecycle transitions cannot be mistaken for content change.
- AML/CFT assessment creation requires an explicit applicable `supervisory_domain_perimeter` record, enforced by the shared `supervisory_assessment_creation_perimeter` rule via a BEFORE INSERT guard on `supervisory_assessment` (browser reads `supervisory_assessment_creation_eligibility`) — so no creation path can bypass it and sector overlay is never mistaken for entity perimeter.
- Role grants in `sec_user_roles` can never be self-granted (`trg_sec_user_roles_no_self_grant`, super admin excepted), and verifier fixtures must grant TEST roles as the TEST super administrator inside a rolled-back transaction — so a leaked fixture can never silently elevate a persona.
- AML/CFT ratings come only from the AML-06 engine run (`supervisory_calc_explain_internal` withholds the whole result if any applicable factor is not calculable) and are approved only via `supervisory_assessment_approve`; the legacy transition cannot set or approve an AML rating — so a caller can never choose or silently re-weight a rating.
- AML/CFT follow-up verification must go through the normal browser user journey: never create test data or calculate assessments via API calls; API calls are allowed only for read-only verification or negative authorization tests — so certification evidence always reflects what a real user can do.
- `WEIGHTED_SCORE` recommendation regressions must use unequal weights that change the outcome versus equal weights, and cover every rounding mode — so a weight-ignoring engine can never pass.
- AML/CFT supervisory judgement is a separate record bound to one calculation run (`supervisory_calculation_override_propose` / `_decide`); a new run marks earlier undecided or unused overrides STALE, approval uses the run's residual (fallback recommended) rating unless an independently approved, non-stale override exists, and the calculation run is never rewritten — so calculated result, judgement and final approved risk always stay distinguishable.
- AML/CFT assessment work (answers, facts, evidence, ratings, calculation, submission) is enforced server-side to the current `owner_id` via `supervisory_assessment_case_actor_require` (super admin excepted); owner/reviewer changes go only through `supervisory_assessment_reassign` (supervisory approval authority, reason, expected current holder, append-only `supervisory_assessment_assignment` history), and unstaffed cases are surfaced by `supervisory_assessment_orphan_cases`, never auto-assigned — so holding AML permissions alone never lets an unrelated officer alter another officer's case.
- AML/CFT official risk-of-record is `entity_risk_state` changed only by `supervisory_assessment_publish_internal` (approval may defer publication; `is_current`/supersession happen at publication, a later-decided publication blocks older ones as `stale_publication`, effect is the publication instant — no future/backdated dates) publication eligibility is decided only by `supervisory_assessment_publication_eligibility_internal`, which both the lifecycle action contract and the publish command use, and movement trend follows `sup_risk_ordinal`; official-risk readers resolve the assessment via `entity_risk_state.driving_assessment_id`, never raw `is_current` (default false); history is answered by `supervisory_entity_risk_as_of` from publication records only — so approval, publication and historical truth can never be confused.
- New Application and New Post-Licence request resolve forms with the regulator that owns the selected sector/licence (post-licence keeps only the chosen service's forms via `matchPostLicenseTemplates`), falling back to the header's active regulator only when none is set — the active regulator is a UI preference that defaults arbitrarily for licensees.
- Examination and examination-finding route gates (`useExaminationGateModule`) accept `inspection_management.view` for prudential-domain records, mirroring `can_read_examination`; RLS still decides entity scope — so the page gate never refuses what the database allows.
- Subscription-package availability is decided only by `src/lib/subscriptionPackages.ts` (features → permission modules) read from the singleton `system_subscription_package`, changed solely via the super-admin `system_subscription_package_set` RPC (history kept); sidebar, AppShell route gate and Entity 360 sections all consult `useSubscriptionPackage` — so a disabled module is hidden everywhere consistently, never shown as a locked placeholder.
- Board Pack breakdowns count every status from paged, caller/RLS-scoped records via `reportStatusCounts`; explicit regulator/sector/record-created-date scope uses `filterReportRows`, excludes unresolved identities only in filtered populations, and travels with exports; read errors are not zero totals — so totals retain provenance and never imply historical as-of truth.
- Executive default return widgets adapt to the canonical workflow-state source and server overdue flag without rewriting historical report definitions; empty denominators and query failures are unavailable, not zero — so current filing KPIs never silently report legacy-only coverage.
- Legacy examination type aliases are supported only by read filters and labels; creation retains canonical engagement values — so historical records stay discoverable without weakening write contracts.
- Registration upload verification is independently restored from fresh server OTP records; submission OTP placement and historical form markers never authorize capability issuance.
- Pending file uploads atomically enqueue deduplicated worker scan jobs; scanner failures remain unreleased and retryable, never reported as completed.
- Detection and management-assurance discoverability mirrors the existing cross-domain supervisory route predicate; menu metadata never grants record access.
- Past-grace renewal is a narrow draft-command exception requiring resolved licence ownership/membership, applicable catalogued renewal service and permitted licence status; ordinary post-licence entitlement remains unchanged.
