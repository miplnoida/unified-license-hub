
# Roles & Permissions — Final Closure Plan

Single pass, no further phased delivery. Every workstream below ships in this turn with automated evidence, or is honestly reported as remaining incomplete.

## 1. Catalogue truth: `enforced` must be real

- Add an `enforced: boolean` column to `src/lib/rbac/catalog.json` entries (or derive from a generated manifest) and a build-time generator `scripts/generate-enforcement-manifest.mjs` that inspects:
  - RLS policies referencing `has_permission` / `has_scoped_permission` per (module, action)
  - RPCs listed in `docs/rbac/rpc-permission-map.tsv`
  - Edge functions in `docs/rbac/edge-function-permission-map.tsv`
  - Storage policies in `docs/rbac/audit-2026-07-21/storage-policies.tsv`
- Any catalogue entry with zero backing enforcement is either implemented in this closure or moved to a `deprecated: true` block with a rationale; no permanent placeholders.
- CI gate `verify-enforcement-manifest.mjs` fails when `enforced=false` appears outside the deprecated list.

## 2. Enforcement matrix — module × surface

Produce and commit `docs/rbac/enforcement-matrix.md` generated by `scripts/generate-enforcement-matrix.mjs` with columns:

```text
Module | SELECT | INSERT | UPDATE | DELETE | RPC | Edge | Storage | Export | Workflow | Dashboard | Bulk | Tests
```

Modules covered: applications, registration, licensing, licensees, returns, prudential, enforcement, inspections, complaints, conduct, reports, audit, settings, role_management, user_management, notifications.

Backend work per module (only where gaps exist today):

- **applications / registration / licensing / licensees**: audit RLS on `applications`, `registrations`, `licenses`, `licensees` and rewrite `SELECT/INSERT/UPDATE/DELETE` policies onto `has_scoped_permission(auth.uid(), '<canonical>', '<action>', record)`.
- **returns**: extend existing scoped policies to cover `return_documents`, `return_upload_attempts`, `return_edit_requests`, `return_data_revisions` for INSERT/UPDATE/DELETE.
- **prudential**: harden `prudential_assessments`, `prudential_actions`, `prudential_escalations` (SELECT already covered; UPDATE/DELETE not).
- **enforcement / inspections**: `enforcement_actions`, `enforcement_case_events`, `inspections`, `inspection_findings` — full CRUD via scoped resolver.
- **reports**: `reports`, `report_run_files`, `report_run_rows`, `report_schedules` — export/download gated by `report_management.export`.
- **admin/config**: lock every `*_config`, `*_rules`, `*_templates` table to `settings.manage_catalog` for writes, `settings.view` for reads.

## 3. Alias removal — canonical namespace

Canonical form (already dominant in catalog): `application_management`, `registration_management`, `license_management`, `licensee_management`, `returns_management`, `prudential_supervision`, `enforcement_management`, `inspection_management`, `complaint_management`, `conduct_management`, `report_management`, `notification_management`, `audit_management`, `settings`, `role_management`, `user_management`.

Steps:

1. `scripts/find-permission-aliases.mjs` walks source + SQL + docs for the alias set (`applications`, `prudential`, `licenses`, `reporting`, `notifications`, `complaints`, `admin`).
2. Automated codemod rewrites UI callers (`useCan`, `<GuardedButton>`, `<M>` route guards, `has_permission` RPC args).
3. Single migration `2026072x_rbac_alias_removal.sql`:
   - Renames rows in `permission_modules` where a duplicate alias exists (data merged into canonical `module_id`).
   - Rewrites every `has_permission` / `has_scoped_permission` call site inside SQL functions using the canonical module string.
   - Drops now-empty alias module rows.
4. `verify-rbac-parity.mjs` gains an `--aliases` sub-check that fails on any alias reappearance.

## 4. Export / download authorization

- New shared helpers:
  - SQL: `public.require_export_permission(_module text, _action text default 'export')` + `public.require_download_permission(_module, _record_id)` — RAISE `not_authorized` on failure.
  - TS (edge): `_shared/exportAuth.ts` wrapping `requireUserPermission` with mandatory scope + dataset filtering hook.
- Every export/download entry point (edge functions `audit-export`, `report-export`, `returns-export`, `application-export`, storage signed-URL RPCs) calls the helper; dataset queries are re-filtered through the scoped resolver before serialization.
- Deno tests assert: 401 unauth, 403 without `<module>.export`, and record-scope filtering (row present for assigned user, absent for other).

## 5. Centralized workflow authorization

- `public.workflow_authorize(_user uuid, _module text, _record uuid, _from text, _to text)` returns `void` and raises on failure. Checks: permission, active role, scoped assignment, current state, allowed transition, SoD (blocks approver == submitter), override flag requires `<module>.override_workflow`, always inserts audit row.
- All workflow RPCs (`execute_complaint_workflow_action`, `execute_return_workflow_action`, `execute_application_workflow_action`, `execute_enforcement_workflow_action`, `execute_inspection_workflow_action`, `execute_prudential_workflow_action`) refactored to call `workflow_authorize` first and remove local role checks.
- pgTAP suite `supabase/tests/rbac/300_workflow_authorization.sql` covers each RPC × (unauth / wrong-scope / SoD violation / valid transition).

## 6. Edge function security sweep

- `scripts/verify-edge-authz.mjs` extended: fail when a function under `supabase/functions/*/index.ts` lacks `requireUserPermission` / `requireWorkerInvocation` / `markPublicFunction`.
- Every user-invoked function receives an `AuthzScope` matching its module (returnId, applicationId, complaintId, etc.). Public functions get an explicit `markPublicFunction(reason)`.
- Deno test coverage extended to the top-risk mutating functions across each module (target ≥25 functions).

## 7. Storage security sweep

- Regenerate `docs/rbac/audit-2026-07-21/storage-policies.tsv` from live policies.
- For every bucket (`application-documents`, `complaint-evidence`, `returns-files`, `prudential-evidence`, `inspection-evidence`, `payment-attachments`, `license-certificates`, `report-outputs`, `audit-exports`, `license-documents`): SELECT/INSERT/UPDATE/DELETE policies routed through `has_scoped_permission` with an object-owner fallback for user-generated evidence.

- pgTAP `supabase/tests/rbac/310_storage_policy_hardening.sql` covers positive + negative per bucket.

## Technical notes

- No project-level `supabase/config.toml` edits.
- All new migrations follow the four-step CREATE / GRANT / RLS / POLICY rule and pin `search_path` on any new SECURITY DEFINER function.
- Alias-removal migration is idempotent and preserves `role_permissions` foreign keys by updating rather than deleting rows during the module merge.
- No frontend UI redesign — changes are limited to authorization strings, guards, and tests.
