# Business-First Roles & Permissions — Completion Plan

Building on the already-shipped foundation (`src/lib/rbac/accessLevels.ts`, module-card UI in `RoleManagement.tsx`, sensitive-privileges section, hidden diagnostics, `accessLevels.test.ts`), this plan closes every remaining gap in the 16-part spec without touching backend enforcement.

## Guardrails (non-negotiable)
- No change to RLS, RPC checks, Edge Function `authz.ts`, storage policies, or `has_permission`.
- `role_permissions` remains the single source of truth. New columns are metadata only.
- All UI simplifications compile down to the same granular permission rows.

## Slice 1 — Database metadata (migration)
Add non-breaking columns and audit table:
- `roles.role_category text` — Operational / Reviewer / Approver / Supervisor / Administrator / Read Only / Custom.
- `roles.status text default 'active'` (active / inactive) + backfill from existing `is_system`/usage.
- `roles.access_summary jsonb` — cached humanized "Can / Cannot" summary (regenerated on save).
- `roles.scope_config jsonb` — per-module record scope (own / assigned / team / department / sector / all). Metadata only; backend RLS already implements these scopes via assignment tables — this column just records the admin's intent so UI reflects it.
- New table `role_migration_log` (role_id, classified_category, matched_template, custom_reason, created_at) with GRANTs + RLS (super_admin/admin read).
- Trigger to keep `access_summary` non-authoritative (regenerated by app on save; DB column is a cache).

## Slice 2 — Role classification & migration
- Extend `src/lib/rbac/accessLevels.ts` with `classifyRole(rolePermissions, allActions)` returning `{ perModuleLevel, sensitive, scope, category, isCustom }`.
- One-time migration script (SQL + TS runner invoked from Admin → Diagnostics button, super_admin only): iterate every existing role, classify, write `role_category` + `access_summary`, log to `role_migration_log`. Permissions untouched.
- Report screen `PermissionMigrationReport.tsx` (super_admin only under System Diagnostics) shows counts: total roles, exact-match per category, Custom, with drill-down.

## Slice 3 — Role editor redesign (business UX)
Rewrite `RoleManagement.tsx` editor into a stepper:
1. **Role Information** — name, description, status toggle, category select (suggestion only).
2. **Module Access** — cards per module, single Access Level dropdown per module. Levels dynamically filtered by `meaningfulLevelsForModule` so e.g. Form Management shows Contributor/Reviewer/Approver, Complaints shows its own set. Add per-module tooltip listing plain-language capabilities the level unlocks.
3. **Record Scope** — per applicable module: Own / Assigned / Assigned Institutions / Team / Department / Sector / All. Backed by `scope_config`; already-enforced by RLS via assignment tables.
4. **Sensitive Privileges** — separate warning-styled panel; checkboxes for Delete, Bulk Delete, Bulk Update, Override Workflow, Publish, Suspend/Revoke/Issue Licence, Manage Users, Manage Roles, Configure Permissions, View All Institutions, Export Confidential, Access Audit Logs. Never auto-set by any level.
5. **Advanced Permissions** — collapsed accordion, `super_admin` only, raw permission checkboxes (current matrix preserved here as escape hatch).
6. **Role Summary** — live "Can ✓ / Cannot ✗" list generated from resolved permission set using humanized labels from `permissionRegistry.ts`.

Validation: block save if any module has Contributor/Reviewer/Approver/Manager without `view`; auto-offer to add view (existing dependency trigger stays as backend belt-and-braces).

## Slice 4 — Business templates
`src/lib/rbac/roleTemplates.ts` with 13 templates listed (Licensing Officer … Administrator, Read Only). Each template = `{ category, perModuleLevel, sensitive, scope }`. "Start from template" button in editor prefills only; admin can modify freely before save. Templates never mutate on save.

## Slice 5 — Terminology cleanup
- Move Permission Coverage Report, RPC Map, Coverage Matrix, Diagnostics under a new `/admin/system-diagnostics` route, `super_admin` only (verify via `<M module="..." />` guard + `isBypassRole`).
- Remove those entries from business admin navigation in `src/config/navigation.tsx`.
- Replace any remaining "36 permissions" style counters with Role Summary component.
- Grep sweep to hide permission IDs/keys from business surfaces (`RoleCard`, list, badges).

## Slice 6 — Custom role handling
- If `classifyRole` returns `isCustom`, badge role card with "Custom" chip, editor opens on Advanced Permissions expanded (super_admin) or read-only summary (business admin) with note "This role uses a custom mix — contact a system administrator to modify."
- Never rewrite custom roles on save unless admin explicitly picks a level.
