# RBAC Backend — Policy Change Log

Chronological record of every policy, helper, and grant introduced or
replaced by the backend RBAC hardening effort. Each entry links the
migration that shipped the change and the pgTAP suite that guards it.

## Phase 1 — Canonical helpers (shipped)

Migration: `supabase/migrations/20260721060418_*.sql`

Added:

- `public.is_super_admin(uuid)` — `SECURITY DEFINER`, `STABLE`, `search_path = public`; executable by `authenticated`, `service_role`.
- `public.has_any_permission(uuid, text[])` — accepts `{"module.action", ...}`, short-circuits on `super_admin`.
- `public.user_has_entity_assignment(uuid, uuid)` — reads `licensees.lead_regulator_id / regulator_officer_id / alternate_regulator_id`.
- `public.is_assignment_only_regulator(uuid)` — mapped on ≥1 licensee **and** zero dynamic-role permissions; super admins excluded.

Replaced (behaviour preserved):

- `public.has_permission(uuid, text, text)` — re-declared to route the super-admin bypass through `is_super_admin` and to lock `search_path = public`. `EXECUTE` revoked from `PUBLIC`.
- `public.can_view_entity_returns(uuid, uuid)` and `(uuid, uuid, text, text)` — refactored to compose the new helpers. Semantics unchanged: `is_super_admin OR has_permission('returns_management','view_all_entities') OR user_has_entity_assignment`.

pgTAP: `supabase/tests/rbac/00_helpers.sql` (24 assertions across four synthetic personas).

No table policies, table grants, or data were touched in this phase.

## Slice 3 — Returns RLS + storage lockdown (shipped)

Migration: `supabase/migrations/*_slice_3_returns_rls.sql`

**New canonical helpers** (SECURITY DEFINER, STABLE, `search_path = public`):

- `public.can_read_return_filed_row(_user, _entity_id, _on_behalf_of_licensee_id, _created_by, _return_id) → boolean`
- `public.can_read_return_filed(_user, _return_id) → boolean`
- `public.can_mutate_return_filed(_user, _return_id) → boolean`

`EXECUTE` revoked from `PUBLIC`; granted to `authenticated, service_role`.
All three route decisions through `is_super_admin` / `has_permission`
(catalog is the single authority), then compose creator, mapped regulator
(any status), licensee membership (`profiles.licensee_id`), `entity_user_access`,
PPOC (`ppoc_mapped_licensee_ids`), and external capability
(`external_can_access_return_filed*`). `can_mutate_return_filed` restricts
licensee/PPOC/external mutation to the editable lifecycle (TEMP/WIP/TBR);
assignment-only regulators can never mutate.

**Table policy rewrites** — dropped every legacy policy on 15 tables and
replaced with the canonical pattern (SELECT via `can_read_*`, INSERT/UPDATE
via `can_mutate_*` or explicit `has_permission`, DELETE via
`is_super_admin` OR `returns_management.delete`):

- `returns_filed` (11 policies → 4)
- `return_form_data` (8 → 4)
- `return_documents` (3 → 4)
- `return_comments` (1 → 4)
- `return_audit_log` (3 → 2, append-only)
- `return_data_revisions` (2 → 3)
- `return_calculated_ratios` (2 → 4)
- `return_consolidated_analysis` (2 → 4)
- `return_edit_requests` (3 → 4)
- `return_requests` (4 → 4)
- `return_notifications_log` (2 → 1, read-only)
- `return_threshold_breaches` (3 → 4)
- `return_upload_attempts` (4 → 4)
- `return_upload_imports` (2 → 3)
- `return_validation_run_log` (2 → 3)

Grants reasserted on every table: `authenticated` CRUD, `service_role` ALL,
`anon` revoked.

**Storage** — `return-uploads` bucket policies replaced:

- Legacy `return_uploads_owner_read / _owner_write / _owner_delete` dropped.
- New `return_uploads_read / _write / _delete` route through
  `can_read_return_filed` / `can_mutate_return_filed`; super_admin and
  `returns_management.view_all_entities` bypass reads.

**Permission catalog** — inserted missing rows if absent:
`returns_management.view_all_entities`, `returns_management.workflow_action`.

pgTAP: `supabase/tests/rbac/40_returns_data_rls.sql` — 30 assertions across
five personas (super_admin, view_all_entities, assignment_only_regulator,
licensee_primary_user, unassociated). Explicit verification that
assignment-only regulators can read all statuses on mapped entities but
cannot mutate anything, and that licensee users can only mutate returns
in the editable lifecycle.

Config/admin tables (`return_configs`, `return_types`, `return_templates`,
`return_cutoff_config`, `return_due_dates`, `return_form_versions`,
`return_notification_templates`, `return_validation_rule*`,
`return_config_forms`, `return_configurations`, `return_template_downloads`)
remain deferred to Phase 4.

## Slice 4 — Returns config/admin table lockdown (shipped)

Migration: `supabase/migrations/*_slice_4_returns_config_rls.sql`

**Permission catalog** — registered `returns_management.manage_config`
(single write authority for every Return configuration surface).

**Policy rewrites** — 12 config/admin tables. Legacy `has_role('admin' |
'super_admin' | 'supervisor')` policies dropped and replaced with the
canonical pattern:

- Reads: open to `authenticated` (needed to render forms, resolve types,
  and display deadlines).
- Writes: `is_super_admin(auth.uid()) OR has_permission(auth.uid(),
  'returns_management','manage_config')`.

Tables covered:

- `return_configs`, `return_configurations`, `return_config_forms`
- `return_types`, `return_templates`
- `return_cutoff_config`, `return_notification_templates`
- `return_validation_rules`, `return_validation_rule_versions`
  (append-only INSERT for permissioned users; read open)
- `return_due_dates`
- `return_form_versions` (SELECT via `can_read_return_filed(return_id)`
  so mapping visibility inherits from the parent return; writes gated by
  `manage_config`)
- `return_template_downloads` (INSERT-self on `downloaded_by`; SELECT
  for owner OR super_admin OR `view_all_entities` / `manage_config`)

**Grants** — every table: `REVOKE ALL ... FROM anon`,
`GRANT SELECT/INSERT/UPDATE/DELETE ... TO authenticated`,
`GRANT ALL ... TO service_role`.

pgTAP: `supabase/tests/rbac/50_returns_config_rls.sql` — 20 assertions
covering catalog registration, `has_permission` composition for three
personas (super_admin, config manager, plain authenticated), presence of
each new write policy, verification that no legacy `has_role()` clause
survives on the 12 tables, and grant assertions (anon = 0 rows,
authenticated SELECT on all 12).

## Slice 5 — Applications & RFI table lockdown (shipped)

Migration: `supabase/migrations/*_slice_5_applications_rls.sql`

**Permission catalog** — added `application_management.view_all_entities`,
`.workflow_action`, `.delete`, `.manage_config` (existing view/create/edit/
approve/reject retained).

**Canonical helpers** (SECURITY DEFINER, STABLE, `search_path = public`;
`EXECUTE` revoked from PUBLIC, granted to `authenticated, service_role`):

- `public.can_read_application(_user, _application_id)` composes
  super_admin, `view_all_entities`, applicant, internal `view`,
  licensee membership (`application_ids_for_licensee`), PPOC mapping,
  and `external_can_access_application(..., 'can_view')`.
- `public.can_mutate_application(_user, _application_id)` composes
  super_admin, `edit`, `workflow_action`, applicant on editable statuses
  (draft/in_progress/resubmission_*/query_raised/returned_for_correction/
  info_requested), and external submit/respond capabilities.

**Policy rewrites** — 8 tables, every legacy multi-role `has_role()` block
replaced with helper composition:

- `applications` (8 policies → 4: read/insert/update/delete)
- `application_ai_assessments` (1 → 2, internal read + permissioned write)
- `application_form_versions` (1 → 2)
- `application_rfis` (2 → 2)
- `application_rfi_items` (2 → 2)
- `application_rfi_responses` (2 → 2, WITH CHECK enforces `submitted_by=auth.uid()`)
- `application_rfi_auto_rules` (2 → 2, read gated to non-external)
- `license_action_form_configs` (2 → 2)

`application_legal_notes` intentionally left as-is: it uses
`has_legal_access()` (not the legacy admin/supervisor pattern) and is the
canonical legal-scope helper.

**Grants** — anon revoked, authenticated CRUD, service_role ALL
reasserted on all 8 tables.

pgTAP: `supabase/tests/rbac/60_applications_rls.sql` — 22 assertions
across five personas (super_admin, view-only staff, edit staff, applicant,
unassociated). Covers helper composition, applicant editable-status
boundary, view-only-cannot-mutate invariant, policy presence, no legacy
`has_role` clauses on the seven child tables, and zero anon grants.

## Slice 6 — Licenses & Licensees lifecycle lockdown (shipped)

Migration: `supabase/migrations/*_slice_6_licenses_licensees_rls.sql`

**Permission catalog** — added:
- `license_management.{view_all_entities, workflow_action, delete, manage_config, manage_certificates, manage_conditions}`
- `licensee_management.{view, create, edit, delete, view_all_entities, manage_products_channels, manage_pre_license}`

**Canonical helpers** (SECURITY DEFINER, STABLE, `search_path = public`;
`EXECUTE` revoked from PUBLIC, granted to `authenticated, service_role`):

- `public.can_read_license(_user, _license_id)` — composes super_admin,
  `view_all_entities`, internal `view`, holder ownership, licensee
  membership (`user_licensee_id` / `license_ids_for_licensee`), PPOC
  mapping, and `external_can_access_license(..., 'can_view_status')`.
- `public.can_mutate_license(_user, _license_id)` — super_admin, `edit`,
  or `workflow_action`.
- `public.can_read_licensee(_user, _licensee_id)` — composes super_admin,
  `view_all_entities`, internal `view`, own profile linkage
  (`profiles.licensee_id`), active PPOC mapping, and assigned
  regulator/supervisor (`lead_regulator_id`, `regulator_officer_id`,
  `alternate_regulator_id`, `assigned_supervisor_id`).
- `public.can_mutate_licensee(_user, _licensee_id)` — super_admin or `edit`.

**Policy rewrites** — 10 tables, every legacy multi-role `has_role()`
block replaced with helper composition:

- `licenses` (5 → 4: read/insert/update/delete)
- `license_actions` (3 → 2, INSERT enforces `actor_id = auth.uid()` with
  `workflow_action`/`manage_license_actions`)
- `license_renewals` (3 → 3, INSERT enforces `initiated_by = auth.uid()`;
  licensee stakeholders retained via `entity_user_access`)
- `license_conditions` (2 → 2, writes gated by `manage_conditions`)
- `license_certificates` (1 → 2, writes gated by `manage_certificates`)
- `license_certificate_signatures` (2 → 1, no authenticated INSERT policy —
  service_role only, so no user session can forge signatures)
- `licensees` (4 → 4)
- `licensee_products` (2 → 2, writes gated by `manage_products_channels`)
- `licensee_channels` (2 → 2, writes gated by `manage_products_channels`)
- `pre_license_users` (5 → 4, self read/write retained; admin writes
  gated by `manage_pre_license`)

**Grants** — anon revoked, authenticated CRUD, service_role ALL
reasserted on all 10 tables.

pgTAP: `supabase/tests/rbac/70_licenses_licensees_rls.sql` — 28 assertions
across seven personas (super_admin, view/edit-permission staff, holder,
assigned lead_regulator, unassociated, licensee viewer). Covers catalog
registration, helper composition, holder/regulator/PPOC pathways,
view-only-cannot-mutate invariant on both entities, assigned-regulator
is read-only, zero legacy `has_role` on any of the 10 tables, and zero
anon grants.

## Slice 7 — Compliance Returns lifecycle lockdown (shipped)

Migration: `supabase/migrations/*_slice_7_compliance_returns_rls.sql`

**Permission catalog** — added `compliance_management.{view, create, edit,
delete, view_all_entities, workflow_action, manage_config, respond,
view_audit_logs}`.

**Canonical helpers** (SECURITY DEFINER, STABLE, `search_path = public`;
`EXECUTE` revoked from PUBLIC, granted to `authenticated, service_role`):

- `public.can_read_compliance_return(_user, _return_id)` — composes
  super_admin, `view_all_entities`, internal `view`, submitter ownership,
  PPOC mapping (`ppoc_mapped_licensee_ids` / `ppoc_accessible_license_ids`),
  and `external_can_access_compliance_return(..., can_view_status|
  can_submit_returns)`.
- `public.can_mutate_compliance_return(_user, _return_id)` — composes
  super_admin, `edit`, `workflow_action`, submitter on editable statuses
  (`draft` / `pending` / `resubmission_requested` / `rejected`), and
  external `can_submit_returns`.

**Policy rewrites** — 2 tables, every legacy multi-role `has_role()` block
replaced with helper/permission composition:

- `compliance_returns` (9 → 4: read/insert/update/delete). INSERT enforces
  `submitter_id = auth.uid()` plus one of: super_admin, `create`, PPOC
  mapping (licensee + accessible license), or external capability gate.
  UPDATE also re-checks external capability on WITH CHECK values so an
  external writer cannot re-target another licensee/license/submitter.
- `compliance_audit_logs` (2 → 1: read only). Read gated by super_admin,
  `view_audit_logs`, or `view_all_entities`; external roles explicitly
  denied. No authenticated write policy exists — audit entries are
  service-role-only, so no user session can forge them.

**Grants** — anon revoked, authenticated CRUD, service_role ALL reasserted
on both tables.

pgTAP: `supabase/tests/rbac/80_compliance_returns_rls.sql` — 20 assertions
across six personas (super_admin, view-only staff, edit staff, submitter,
audit-log reader, unassociated). Covers catalog registration, helper
composition, submitter editable-status boundary (draft mutable,
approved locked), view-only-cannot-mutate invariant, zero legacy
`has_role`, zero anon grants, and no authenticated write policy on
`compliance_audit_logs`.







## Slice 8 — Approval Workflow & Collaborative Review Lockdown

**Permissions** — 4 new `workflow_management` actions registered:
`delete`, `workflow_action`, `manage_config`, `view_all`.

**Helpers** — 4 new SECURITY DEFINER helpers with pinned `search_path`:

- `can_read_approval_config(_user)` — super_admin OR
  `workflow_management.view` OR `workflow_management.manage_config`.
- `can_mutate_approval_config(_user)` — super_admin OR `manage_config`.
- `can_act_on_approval(_user)` — super_admin OR `workflow_action` OR
  `manage_config`. Used to gate `approval_actions` inserts and
  `workflow_instances` writes.
- `can_read_workflow_instance(_user, _entity_id)` — super_admin OR
  `view` OR `view_all` OR the applicant owns the source application.

**Policy rewrites** — 16 tables, every legacy multi-role `has_role()`
block replaced with helper composition:

- Configuration surface (read = `can_read_approval_config`, write =
  `can_mutate_approval_config`): `approval_workflows`,
  `approval_workflow_versions`, `approval_workflow_types`,
  `approval_steps`, `approval_step_actions`, `delegation_rules`,
  `workflow_templates`, `approval_action_notifications`,
  `approval_step_entry_notifications`.
- `approval_actions` (4 policies): SELECT for own row / config readers
  / actors; INSERT pins `actor_id = auth.uid()` and requires
  `can_act_on_approval`; UPDATE gated by `manage_config`; DELETE
  reserved for super_admin.
- `workflow_instances` (2 policies): applicants can read their own
  instance via `can_read_workflow_instance`; writes require
  `can_act_on_approval` or `manage_config`.
- Collaborative review (`review_comments`, `review_suggestions`):
  entity-scoped visibility via `can_access_review_entity`; INSERT pins
  `author_user_id = auth.uid()`; UPDATE/DELETE restricted to author or
  collab admin.
- `review_step_permissions`, `review_role_display_settings`,
  `review_narrative_fields`: read open to authenticated (required for
  render), writes gated by `is_collab_admin` (plus `manage_config` for
  narrative fields).

**Grants** — anon revoked, authenticated CRUD, service_role ALL
reasserted on all 16 tables.

pgTAP: `supabase/tests/rbac/90_approval_workflows_rls.sql` — 24
assertions covering helper composition, applicant carve-out, per-table
policy shape, absence of legacy `has_role()`, and new permission
registration.
